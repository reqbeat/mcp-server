# Reqbeat Hiring Signals

Find companies hiring for a role and geo, qualify them, and watch them for changes.

## When to use this skill

Use it when the question is about **who is hiring** — sourcing companies by role and
location, checking whether a named company is hiring, or watching a company for a
change in its hiring. It answers from job postings collected off employers' own
applicant-tracking systems, so the unit of truth is an open requisition, not a profile
or a press mention.

## Try it before connecting anything

One `GET`, no key, real rows off the live index:

```bash
curl -s 'https://api.reqbeat.com/v1/sandbox/reqs/search?role=backend+engineer&geo=United+States'
```

Parameters: `role` (free text over the posting title), `geo` (country),
`since` (ISO-8601 lower bound on first-seen), `limit`.

The sandbox serves one page of at most 25 companies and takes no
cursor. A non-null `next_cursor` in the response means the corpus continues past what a
keyless call may read — it is a signal, not a paging handle. Connect below to page it.

## Connect

`com.reqbeat/hiring-signals` v1.1.2, over streamable-http:

```json
{
  "mcpServers": {
    "com-reqbeat-hiring-signals": {
      "url": "https://mcp.reqbeat.com/mcp",
      "headers": {
        "X-API-Key": "YOUR_REQBEAT_API_KEY"
      }
    }
  }
}
```

Replace the placeholder with your own key.

Or connect with no key at all. Same endpoint -- leaving the `X-API-Key` header
off runs the read tools in a rate-limited demo mode, so this skill can be tried before
anyone signs up:

```json
{
  "mcpServers": {
    "com-reqbeat-hiring-signals": {
      "url": "https://mcp.reqbeat.com/mcp"
    }
  }
}
```
